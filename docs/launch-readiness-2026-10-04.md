# Launch readiness audit

Target: 1,000 simultaneous users, rapid and random interactions. Production: https://yemunnai.vercel.app. Started 2026-10-04.

## Launch decision

Not ready for live ordering. Production pickup endpoint returns 404; anonymous buyer sign-in is disabled. Both available token sources return 403, `Missing required permission(s): database_read`. The user has authorized repairs, but Supabase still denies access. No real production orders or destructive load traffic are generated by this audit.

## Baseline

Existing checkout, Saved/account race, manual stock, seller deletion, and image-cache suites pass. Previous live filter checks passed 72 combinations. These tests cover behavior; they do not prove production capacity.

## Findings

1. Reviews use React state alone to guard writes, allow Escape during submission, and leave delayed close timers running after unmount. Rapid clicks can submit twice or close the wrong sheet.
2. Reaction writes swallow errors. The buyer sees a saved like even when the write fails; concurrent clicks can race and inflate counts. Initial reaction loading can overwrite a recent click.
3. Browsing creates multiple catalog subscriptions per visitor and independently polls menu and shops every 15 seconds. A thousand browsers generate avoidable database requests and realtime connections.

4. Collection confirmation also uses React state alone, allowing simultaneous callbacks. It now takes an immediate lock; ten rapid collection clicks execute one transition.
5. A seller publishing confirmation can retain a delayed close after the sheet has been closed and reopened. Closing cancels the timer and resets a successful form; unsent drafts are preserved.
6. Discovery can substitute static SVG catalogue artwork solely because live data contains 40 items. Native cards now always display the actual seller data, prices and dietary declarations.
7. Unknown-price cards repeat Unavailable in both the price and action. The price slot now shows a dash with an accessible explanation; the action retains Unavailable.

## Completed fixes and verification

Public catalogue reads share a five-second server/CDN cache and concurrent menu/shop requests. No caller token or private columns are forwarded or cached. A proxy failure falls back to the existing public REST reads, with a sixty-second proxy cooldown. Buyer catalogue and order views no longer each allocate dedicated realtime connections; jittered polling stops while the tab is hidden. Seller order subscriptions remain.

Passed: TypeScript and production build; checkout duplicate/lost-response/recovery tests; Saved and private account races; manual stock, seller deletion and image caching; actual Chrome buyer-to-seller fixture flow; quiet dashboard retries, modals and installation; four-width intro and bookmark persistence; 72 filter combinations; Veg/Non-veg/unknown labels and price/action alignment at 320 and 390px; duplicate review submission and failed-like rollback; 1,000 seeded random UI actions without overlapping dialogs, horizontal overflow or unhandled errors.

A transport simulation with 1,000 simultaneous catalogue readers performs two upstream reads per cold server instance and passes cache expiry, outage and privacy checks. This is not a production concurrency benchmark. Live ordering, real database writes, realtime capacity and the production service plan remain unverified because production access is denied and pickup is not deployed.

The user approved the premium SVG header, which is now implemented using the same layered orange SVG background and native interactive controls. Header geometry, selection/clear actions, search sizing and cart navigation pass browser checks at four widths. This visual release does not resolve the production ordering blockers above.
